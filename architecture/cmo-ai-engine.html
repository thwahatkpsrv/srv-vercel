01 — Why the middleware

What the AI Engine is responsible for

Core responsibility

The middleware is the orchestration/service layer between authorised CMO/front-end modules and approved AI processing services. It normalises requests, applies policy controls, invokes the appropriate AI capability, validates results and returns auditable outputs.

Source boundary: the document defines the AI Engine as middleware + Conversation Streaming API + AI-Analyzed Detailed Report API. It explicitly says the exact internal API grouping is to be finalised during detailed design.
In

AI orchestration

OCR, STT, summarisation, semantic similarity, analytics, sentiment and reply checks.

In

Conversation streaming

Real-time token-streamed responses for plain-language query and helpline assistance.

In

Detailed analytics

Structured trends, sentiment, systemic clusters and forecasts for dashboards.

Out

Core portal authority

Official DB, authentication/RBAC, workflow and administrative decisions remain with C-DIT/CMO.

05 — Output contract

AI output is evidence for a human decision

{ "request_id": "CMO-2026-000981", "status": "REVIEW_REQUIRED", "result": { "summary": { "text": "...", "confidence": 0.94 }, "suggestions": { "category": {"value":"...", "confidence":0.88}, "priority": {"value":"high", "confidence":0.82} }, "related_cases": [ {"case_ref":"masked-001","similarity":0.91} ] }, "guardrails": { "pii_masked": true, "human_review": true, "decision_authority": "officer" }, "trace": { "model": "approved-model-id", "model_version": "x.y", "policy_version": "p.z" } }

Confidence

Expose field/result confidence where applicable. Low-confidence or high-impact outputs route to review.

Editable

Officer can accept, edit, reject or override AI suggestions before final use.

Traceable

Log AI suggestion and officer outcome through approved system integration.

Non-authoritative

The engine returns assistance, not a final administrative action.

Important: citizen notifications may be generated by the engine, but dispatch remains a portal/gateway function. The engine should not silently send notifications.

06 — Guardrails

Guardrails are part of the architecture, not an add-on

🔐

Access

Role-aware context; approved interfaces; no direct production DB access.

🛡

Privacy

Minimise, mask/redact PII, encrypt, retain only for approved periods.

🎯

Scope

Block unsupported actions and prevent AI from becoming the workflow authority.

🧑‍⚖️

Human-in-loop

Low-confidence/high-impact outputs require review; decisions remain with officials.

📋

Audit

Prompt/response, confidence, model/version, edits and final actions are traceable.

ALLOW

Assist

Summarise, transcribe, detect related cases, flag risk, analyse trends, suggest classifications.

REVIEW

Human gate

Identity matches, fuzzy profile matches, duplicate/common-issue tags, routing/priority suggestions and closure-quality flags.

BLOCK

No autonomous authority

No auto-merge, auto-tag, auto-close, final administrative decision or direct production DB write.

11 — Security, privacy & observability

Production controls

Data protection

  • Encryption in transit and at rest
  • Secure secrets
  • OWASP controls
  • Malware scanning
  • Minimum necessary access

Governance

  • India data residency unless approved otherwise
  • No training of public/general-purpose models using Government data
  • External AI provider requires prior approval
  • Purpose-limited retention

Observability

  • Central logs, metrics and alerts
  • Trace IDs
  • Model/version logging
  • Operational dashboards
  • AI suggestion + officer outcome history

Performance & availability

Interactive screens: target ≤3 seconds excluding external AI/model processing. Startup-developed production services: ≥99.5% availability, excluding approved maintenance/upstream failures.

Scalability & interoperability

Modular, API-first, container-ready; horizontal scaling based on historical/peak volume analysis; open standards and documented REST/JSON APIs or approved equivalent.

13 — Decisions before detailed design

What should be frozen before implementation

SCOPE DECISION

Routing suggestion boundary

The document contains a scope inconsistency: one scope table says department/category routing suggestion is not part of the AI Engine, while later functional sections explicitly include department/category/priority suggestions. Resolve this before API/SRS freeze.

API DECISION

Logical API grouping

The document names middleware, Conversation Streaming API and AI-Analyzed Detailed Report API, but explicitly says the exact internal API grouping/endpoints are not mandated. Freeze the final contract during detailed design.

DATA DECISION

Approved data/context

Define the exact C-DIT APIs, master-data versions, historical-data access mechanism, masking rules and allowed fields for each AI operation.

MODEL DECISION

Model/provider policy

Source does not mandate a specific AI/LLM/OCR/STT/embedding model. Final technology must satisfy accuracy, performance, security, scalability, cost and Government approval requirements.

Recommended design rule: freeze policy contracts first — scope, identity, data access, confidence thresholds, human-review states, audit events and fallback — then optimise model/provider selection behind those contracts.
